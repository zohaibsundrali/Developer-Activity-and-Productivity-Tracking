# Shift attendance exceptions

The Shift schedule screen now includes an exception report for ended, published shifts. Late arrival and early departure both default to a five-minute grace period, as chosen for this implementation with the user's authorization. Report viewers can change each threshold from 0 to 120 minutes. These are report inputs, not a saved organization payroll policy; they do not deduct work time or money.

The report identifies late arrival, early departure, missing checkout and missed shifts. Exact grace boundaries are accepted; displayed differences are the full difference from the scheduled clock, not the difference minus grace. Future/ongoing, draft and cancelled shifts are excluded. UTC shift-start dates define the report range. Overnight and DST calculations use real instants and each shift's timezone for leave-day coverage.

Daily attendance records are not task timers or mobile GPS sessions. The report uses attendance clocks and approved leave, never inferring attendance from productivity activity. A single daily clock spanning multiple shifts, multiple matching clocks, partial-day/partial-shift leave, or contradictory status/clock evidence goes to manual review. Full leave or holiday coverage must cover every local calendar date touched by the shift. Missing or ambiguous evidence must be reconciled by an attendance manager before treating a flag as a confirmed absence.

Managers with both attendance.manage and attendance.view_all can acknowledge, excuse or reopen a review with a reason. Each review retains its author, timestamp, exact source evidence and grace inputs. Repeating the same request ID is idempotent. Changed source evidence or grace invalidates the earlier review; historical decisions remain visible. Reviews do not edit clocks, approve timesheets, change leave or affect payroll. Clock-editing UI is outside this change.

Own reports and review reads bind organization, profile ID and profile type. Organization reports require attendance.view_all. Explicit denials apply to both API and database; browser results are invalidated on account, permission and filter changes. Report snapshots are read in one SQL statement. The API returns a complete range of up to 31 dates / 500 shifts / 5 MB of evidence, or asks for a smaller range instead of silently truncating. Up to 20 recent review entries per shift appear in the report; the full audit remains in shift_attendance_reviews. Leave reasons, attendance notes and GPS are excluded from the evidence snapshot.

## Deployment and validation

Apply `20260914174305_production_shift_attendance_exceptions.sql` after the existing attendance, typed-leave and shift-scheduling migrations. It adds RLS-protected immutable review records, guarded caller RPCs and private evidence collection. Explicit grants are included for current [Supabase Data API exposure requirements](https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically).

Run `bash scripts/test-shift-attendance-exceptions.sh` for disposable PostgreSQL contracts, and the shiftAttendanceExceptions / shiftExceptionsApi / shiftExceptionsView Vitest suites for calculations and application behavior. No hosted migration has been applied. After staging DDL, run security/performance advisors and verify real manager/employee accounts, denied access, approved half/full leave, an overnight shift, clock correction followed by re-review and billing-locked writes. Recurring schedules, notifications, automatic penalties and direct clock correction remain separate work.
